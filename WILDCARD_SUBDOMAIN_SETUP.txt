================================================================================
  SMSLY Hosting — Wildcard Subdomain Setup
  Enables: my-app.cloud.smsly.cloud for every deployed service
  VPS IP: 209.159.155.100
================================================================================

STEP 1: CLOUDFLARE DNS (browser)
─────────────────────────────────
1. Go to Cloudflare → smsly.cloud → DNS → Add Record
2. Add:
     Type: A
     Name: *.cloud
     Content: 209.159.155.100
     Proxy status: DNS only (grey cloud — free plan can't proxy wildcards)
3. Save. Verify with: nslookup test.cloud.smsly.cloud


STEP 2: INSTALL CADDY WITH CLOUDFLARE MODULE (VPS)
───────────────────────────────────────────────────
systemctl stop caddy

# Install Go (needed for xcaddy)
apt install -y golang 2>/dev/null || true

# Install xcaddy
go install github.com/caddyserver/xcaddy/cmd/xcaddy@latest

# Build custom Caddy with Cloudflare DNS plugin
~/go/bin/xcaddy build --with github.com/caddy-dns/cloudflare

# Replace system Caddy binary
mv ./caddy /usr/bin/caddy
chmod +x /usr/bin/caddy

# Verify
caddy version
caddy list-modules | grep cloudflare


STEP 3: CREATE CLOUDFLARE API TOKEN (browser)
─────────────────────────────────────────────
1. Go to: https://dash.cloudflare.com/profile/api-tokens
2. Click "Create Token"
3. Use template: "Edit zone DNS"
4. Zone Resources: Include → smsly.cloud
5. Create and COPY the token

Then on VPS, save it:

echo "CLOUDFLARE_API_TOKEN=paste_your_token_here" > /etc/caddy/cloudflare.env
chmod 600 /etc/caddy/cloudflare.env


STEP 4: UPDATE CADDYFILE (VPS)
──────────────────────────────
cat > /etc/caddy/Caddyfile << 'EOF'
# SMSLY Hosting — Reverse Proxy
# Main dashboard + wildcard service subdomains

cloud.smsly.cloud {
    reverse_proxy localhost:8090
    encode gzip
    log {
        output file /var/log/caddy/access.log
    }
}

*.cloud.smsly.cloud {
    tls {
        dns cloudflare {env.CLOUDFLARE_API_TOKEN}
    }
    reverse_proxy localhost:8081
    encode gzip
    log {
        output file /var/log/caddy/wildcard.log
    }
}

:80 {
    reverse_proxy localhost:8090
}
EOF


STEP 5: UPDATE CADDY SYSTEMD & RESTART (VPS)
─────────────────────────────────────────────
mkdir -p /etc/systemd/system/caddy.service.d

cat > /etc/systemd/system/caddy.service.d/override.conf << 'EOF'
[Service]
EnvironmentFile=/etc/caddy/cloudflare.env
EOF

systemctl daemon-reload
systemctl start caddy
systemctl status caddy

# Check logs if issues:
journalctl -u caddy --no-pager -n 50


STEP 6: VERIFY (from any machine)
─────────────────────────────────
curl -I https://test-app.cloud.smsly.cloud
# Should return 200 OK with valid SSL certificate

nslookup anything.cloud.smsly.cloud
# Should resolve to 209.159.155.100


NOTES:
- All *.cloud.smsly.cloud subdomains route to Traefik (localhost:8081), which forwards to per-service containers
- The backend auto-generates subdomains like: my-app-abc123.cloud.smsly.cloud
- Custom domains can still be added per-service via the Domains tab
- If Caddy fails to start, check: journalctl -u caddy -f
